# 1. Overview

This document defines the long-term development roadmap for Hrafnar.

The roadmap provides a high-level view of the project's evolution from the initial prototype to the full release.

Rather than focusing on dates, the roadmap is organized into development phases. Each phase builds upon the previous one, ensuring that the project grows in a stable and maintainable way.

Detailed objectives for each phase are documented separately in `Milestones.md`, while day-to-day work is planned in the Sprint documents.

---

# 2. Development Philosophy

The project follows an iterative development process.

Each phase should produce a stable, playable version of the game before moving on to the next stage.

Core principles:

- Build a solid foundation first.
- Validate gameplay early.
- Expand systems incrementally.
- Prioritize quality over speed.
- Avoid unnecessary complexity.
- Keep the project playable at all times.

# 4. Phase Details

## Phase 1 — Foundation

Objective:

Establish the technical foundation of the project.

Primary focus:

- Project setup
- Repository organization
- Documentation
- Core architecture
- Coding standards
- Basic framework systems

Outcome:

A clean, scalable and maintainable project ready for gameplay implementation.

---

## Phase 2 — Core Gameplay

Objective:

Implement the core gameplay loop.

Primary focus:

- Resources
- Buildings
- Towers
- Enemies
- Waves
- Fog of War

Outcome:

A fully playable gameplay prototype demonstrating the project's core mechanics.

---

## Phase 3 — Vertical Slice

Objective:

Create a polished example of the final gameplay experience.

Primary focus:

- Complete gameplay loop
- Visual improvements
- Audio implementation
- UI/UX refinement
- Game balancing

Outcome:

A representative slice of the finished game suitable for testing and presentation.

---

## Phase 4 — Content Expansion

Objective:

Increase gameplay variety.

Primary focus:

- New towers
- New enemies
- Additional buildings
- Maps
- Biomes
- Difficulty options
- Additional mechanics

Outcome:

A feature-rich game with increased replayability.

---

## Phase 5 — Polish & Optimization

Objective:

Improve the quality and performance of the game.

Primary focus:

- Performance optimization
- Bug fixing
- Animation polish
- VFX
- Audio polish
- Accessibility improvements
- Final balancing

Outcome:

A stable and polished experience ready for release.

---

## Phase 6 — Release Preparation

Objective:

Prepare the project for public release.

Primary focus:

- Final QA
- Documentation review
- Store assets
- Build verification
- Release candidate testing
- Marketing materials

Outcome:

A release-ready version of the project.

---

## Release

Objective:

Publish the first public version of the game.

Primary focus:

- Launch
- Community support
- Hotfixes
- Monitoring

Outcome:

Successful public release.

---

## Post-Launch Support

Objective:

Continue improving the game after release.

Potential areas:

- Additional content
- Balance updates
- Quality-of-life improvements
- Seasonal events
- Community feedback
- Performance improvements

Outcome:

Long-term support and continued growth of the project.

---

# 5. Roadmap Principles

The roadmap follows several guiding principles:

- Every phase must have a clear objective.
- Each phase should end with a stable build.
- Large features should be divided into smaller milestones.
- Gameplay validation should occur before content expansion.
- Quality is more important than development speed.

The roadmap may evolve during development, but changes should always support the project's long-term vision.

---

# 6. Future Expansion

The roadmap is designed to accommodate future development without major restructuring.

Possible long-term additions include:

- New game modes
- Additional factions
- Hero units
- Procedural maps
- Endless mode
- Cooperative multiplayer
- Mod support
- Downloadable content (DLC)

These features are not part of the initial release scope but remain compatible with the project's architectural goals.
